# Eye Care 20-20-20 Timer Design

## Goal

Build a personal-use iOS app that prompts the user to look about 20 feet away for 20 seconds after every 20 minutes of near work. The session continues in the background until the user presses Stop. Locking the device pauses the session; unlocking within 60 seconds resumes it, while a longer lock resets the work phase and starts a fresh cycle automatically.

## Scope

The first version contains one primary screen, fixed 20-minute and 20-second durations, local notification prompts, manual start and stop, lock-aware pause/reset behavior, and background audio keep-alive. Settings, history, accounts, analytics, sync, and App Store distribution are out of scope.

## User Flow

1. The app opens in Idle with a 20:00 display.
2. Tapping Start begins Work and requests notification permission.
3. When Work reaches zero, the app shows and sends “Look 20 feet away” and enters a 20-second Look Away phase.
4. When Look Away reaches zero, Work restarts automatically.
5. Tapping Stop ends the session and cancels pending notifications.
6. Locking the device pauses the current phase and cancels pending notification requests.
7. Unlocking within 60 seconds resumes the phase with its saved remaining time.
8. Unlocking after more than 60 seconds resets to Work at 20:00 and starts immediately.

## Interface

The main screen uses a calm dark-green gradient, a large circular progress ring, one primary timer in monospaced digits, a short state label, and a full-width Start/Stop button. Work and Look Away use distinct accent colors. The current cycle count is secondary information, not a control.

## Architecture

- `TimerCore`: pure, deterministic state machine using an injected `Date`.
- `TimerViewModel`: owns the core, refreshes UI, reacts to transition events, and coordinates services.
- `LockObserver`: observes protected-data availability notifications.
- `NotificationScheduler`: requests permission and schedules/cancels one local notification per phase deadline.
- `BackgroundAudioKeeper`: maintains a silent looping playback session while the timer runs.

## State Model

States are Idle, Running Work, Running Look Away, and Locked. A lock stores the phase, remaining time, and lock start date. Unlock compares the lock duration with the 60-second threshold. Transitions are generated by explicit calls and by `tick(at:)`; the UI never decides state.

## Background and Lock Behavior

The app keeps a silent audio playback session active during a running timer, enabling prompt protected-data handling while backgrounded. On `protectedDataWillBecomeUnavailable`, it pauses and removes pending prompts. On `protectedDataDidBecomeAvailable`, it applies the resume/reset rule. The work deadline also has a local notification so the look-away prompt is delivered if the process is delayed. The 20-second look-away phase does not send a second notification.

This approach is for personal sideloading. Silent background audio is not an App Store-safe use of the audio background mode, may increase battery use, and can expose playback presence on the Lock Screen.

## Error Handling

- If notification permission is denied, the in-app phase change still explains the break; a non-blocking status message tells the user to enable notifications for background prompts.
- If audio cannot start, the timer continues with timestamp-based scheduling and local notifications, but immediate background lock handling may be less reliable.
- If the user force-quits the app, the session ends, which matches the manual-stop model.
- Clock changes are accepted as wall-clock changes; the app clamps negative remaining durations to zero.

## Testing

Unit tests cover initialization, starting, reaching the work boundary, completing the look-away phase, lock pause, the 60-second boundary, short-lock resume, long-lock reset, and stop. Structural checks validate required files and build settings. Physical iPhone testing covers real lock events, background switching, notification delivery, silent audio, and battery behavior.

## Acceptance Criteria

- A started timer visibly counts down from 20:00.
- Work completion triggers a look-away prompt and a 20-second phase.
- Look-away completion starts a new work phase automatically.
- Lock cancels prompts and pauses progress.
- Unlocking at 60 seconds resumes; 61 seconds resets to 20:00 and starts.
- Only Stop or force-quitting ends the repeating session.
